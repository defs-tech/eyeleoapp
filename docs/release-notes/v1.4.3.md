One change over 1.4.2.

- A finished steep now makes the system's own "Windows Unlock" sound, taken from
  `C:\Windows\Media`. It is a file and not an event, so it is played by path rather than by alias,
  and both spellings the system uses for it are tried: `WindowsUnlock.wav` and
  `Windows Unlock.wav`. Which one it settled on is written to the log on the first steep.
- If the machine has neither, it falls back to the notification event as before. Nothing ships with
  the app either way, and the "Enable sounds" setting still decides whether a steep says anything.

Note that the sound no longer follows the user's sound scheme: it is the same file on every Windows
that ships it, rather than whatever that scheme has bound to the notification event.
