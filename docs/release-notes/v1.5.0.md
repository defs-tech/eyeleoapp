The dynamic menu: the teas come from `tea.conf` rather than from the program, and adding one no longer
needs a rebuild.

This is 1.5.0. What is in it, newest first:

- The list of teas is read from `tea.conf` instead of being compiled in. A line added to that file
  turns up in the menu; a line deleted disappears from it, and the menu follows the file in the file's
  order. There is no second list anywhere in the program any more.
- A line is taken whole or refused whole, and the refusal says why. Refused are a name that is not one
  lowercase Latin word, a temperature outside (0, 100], a steep time that is not a whole number of
  seconds, more than eight of them, and a name already given. A rejected line leaves nothing behind,
  and the rest of the file is still used; only a file with nothing usable in it falls back to the
  built-in schedules.
- Names are held to a stricter shape than before. Earlier versions accepted English or Russian
  spellings in any case, which meant a typo silently kept the built-in schedule and a name differing
  only in case could pick up another tea's picture. Uppercase is now refused rather than folded, because
  Windows treats `Tea.png` and `tea.png` as one file.
- A vessel is looked up by name, `Resources\tea_<name>.png`, and checked when it loads: PNG, 8 bits a
  sample, colour type 6 so there is a real alpha channel, and no larger than 71x44 px, the corner of
  the bubble. Anything failing that is refused and the slot is left empty. A tea with no picture still
  brews, it just has no glass.
- The app no longer adds missing lines to your `tea.conf`. It used to: a tea introduced by a later
  version was not in the file, so the file went on not naming a tea that was in use, and an edit to it
  looked as though it should apply and did not. The lines were added once, in the shipped wording, and
  never removed again. **A file with fewer teas than the app ships now means those teas, and the app
  will not put the rest back.** That is the visible change to be aware of here.
- The log is off unless `EYELEO_DEBUG=1` is set, the same switch macOS uses:
  `set EYELEO_DEBUG=1 && EyeLeo.exe`. The file is `%APPDATA%\EyeLeo\log.txt`. It used to be written
  always, and every refusal above goes there, so if a tea you added is not in the menu this is what to
  turn on first. Nothing is written and no file is created when the switch is off.
- The tea menu can show 500 teas. The list itself is not capped; a file with more than that is truncated
  in the menu and says so in the log.

Water is not a tea. It has no steeping schedule, it cannot be added to `tea.conf`, and it is not in the
tea menu. It is the hydration reminder with its own settings and its own glass.

One bug fixed on the way, older than this release: a `tea.conf` whose last line had no newline made the
parser loop for ever. A one-line file written by hand is exactly that.
