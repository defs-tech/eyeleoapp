# Как пользоваться чаями в EyeLeo

Полное описание того, как устроен список чаёв, и как добавить свой. Рассчитано на человека, который
никогда не открывал исходный код и не собирал программу.

Коротко: **чаи задаёт файл `tea.conf`**. Картинка сосуда и подпись в меню связаны с ним по имени, но
лежат в других местах. Ниже — все три места и точный порядок работы.

---

## 1. Где что лежит

### Windows

| Что | Где |
|---|---|
| Расписания чаёв | `%APPDATA%\EyeLeo\tea.conf` |
| Настройки | `%APPDATA%\EyeLeo\settings.xml` |
| Журнал | `%APPDATA%\EyeLeo\log.txt` — **только** при `EYELEO_DEBUG=1`, иначе файла нет |
| Шаблон расписаний | `C:\Program Files\EyeLeo\tea.conf` — **не редактировать** |
| Картинки сосудов | `bin\Resources\` рядом с `EyeLeo.exe` |

Быстрый путь в папку: **Проводник → в адресную строку `%APPDATA%\EyeLeo` → Enter**.

### macOS

| Что | Где |
|---|---|
| Расписания чаёв | `~/Library/Containers/local.eyeleo.EyeLeo/Data/Library/Application Support/EyeLeo/tea.conf` |
| Настройки | `~/Library/Containers/local.eyeleo.EyeLeo/Data/Library/Preferences/local.eyeleo.EyeLeo.plist` |
| Журнал | там же, `log.txt` — **только** при `EYELEO_DEBUG=1` |

Быстрый путь в папку: **Finder → Cmd+Shift+G** → вставить
`~/Library/Containers/local.eyeleo.EyeLeo/Data/Library/Application Support/EyeLeo` → Enter.

Либо одной командой в терминале:

```sh
open ~/Library/Containers/local.eyeleo.EyeLeo/Data/Library/Application\ Support/EyeLeo
```

Почему так глубоко — отдельный вопрос, он разобран в самом конце документа.

## 2. Файл `tea.conf`

Одна строка — один чай:

```
имя, температура, секунда1, секунда2, секунда3, ...
```

Живой пример из файла, который поставляется с программой:

```
green, 80, 10, 15, 20, 25, 30, 35
white, 85, 10, 15, 20, 25, 30
oolong, 85, 15, 25, 35, 45, 60, 75
black, 90, 20, 30, 40, 50, 60, 70
red, 95, 7, 10, 15, 20, 25, 30
puer, 99, 20, 30, 40, 50, 60, 70, 80, 90
herbal, 100, 300, 360, 420, 480
```

Строка `green, 80, 10, 15, 20, 25, 30, 35` означает: чай зовётся `green`, вода 80 °C, шесть проливов
длительностью 10, 15, 20, 25, 30 и 35 секунд.

Строки, начинающиеся с `#`, и пустые строки игнорируются. Это единственный способ что-то закомментировать
в файле.

### Требования к имени

Имя — это не украшение, а **идентичность чая**. По нему ищется картинка, по нему же ищется подпись в
меню. Поэтому форма жёсткая:

| Правило | Пример |
|---|---|
| Только строчная латинская буква | `a`–`z` |
| Первая — буква | `pu_er` да, `2oolong` нет, `_oolong` нет |
| Дальше буквы, цифры, подчёркивание | `milky_oolong`, `oolong2`, `pu_er` |
| Одно слово, без пробелов | `milky_oolong` да, `milky oolong` нет |
| Не длиннее 24 знаков | |

**Почему нет кириллицы.** Раньше программа принимала русские названия. Теперь нет: имя становится
именем файла картинки, а файловая система macOS по умолчанию не различает регистр, и `Чай.png` с
`чай.png` — это один файл. Чай, отличающийся от соседа только регистром, молча подхватил бы чужую
картинку. То же самое с пробелом и с очень длинным именем.

**Почему не длиннее 24 знаков.** Тот же довод: имя целиком становится именем файла.

### Температура

Число больше 0 и не больше 100. Температура **только показывается в подписи** — на что-то заваривание не
влияет.

### Времена проливов

От 1 до 8 штук, каждое — целое число секунд от 1 до 3600.

**Почему восемь.** Это длина самого длинного расписания из поставляемых, пуэрского. Число взято не с
потолка: больше восьми проливов заваривать бессмысленно.

**Почему 3600.** Час — верхняя граница, отделяющая опечатку от реального расписания. Самое длинное из
поставляемого — травяной, 300 секунд, то есть вдвое с запасом.

### Порядок в меню

Меню идёт **строго в порядке строк файла**. Первая строка — первый пункт. Перенесли строку — переехал
пункт. Удалили — чая больше нет.

### Что программа НЕ делает

- **Не дописывает за вас строки.** Если в файле пять чаёв, в меню пять чаёв. Отсутствующие не
  возвращаются. Это сделано намеренно: меньше — значит так задумано.
- **Не чинит и не переписывает файл.** Ваш файл остаётся ровно таким, каким вы его написали.
- **Не трогает воду.** Её в этом файле быть не может, см. раздел 7.

## 3. Картинка сосуда

К названию чая картинка **не прописывается**. Она находится по имени файла:

```
Resources\tea_<имя>.png
```

Для чая `milky_oolong` это `Resources\tea_milky_oolong.png`.

### Проще всего — скопировать

Готовый сосуд всегда в комплекте, и копия его заведомо правильная:

```sh
# Windows
copy bin\Resources\tea_green.png bin\Resources\tea_milky_oolong.png

# macOS
cp Resources/tea_oolong.png Resources/tea_milky_oolong.png
```

На Windows после этого достаточно перезапустить программу. На macOS — см. предупреждение ниже.

### Если делаете картинку сами

| Требование | Windows | macOS |
|---|---|---|
| Формат | PNG | PNG |
| Глубина | 8 бит на канал | 8 бит на канал |
| Тип цвета | 6 (RGB с альфой) | 6 (RGB с альфой) |
| Размер | не больше **71×44** px | не больше **142×88** px |

Почему разный размер: Windows рисует сосуд в натуральную величину, macOS — вдвое крупнее, чтобы картинка
была резкой на Retina. Слот в пузыре один и тот же — 71×44 точки.

**Альфа-канал обязателен.** Без него картинка покажется чёрным прямоугольником. Это самая частая ошибка,
и её трудно заметить, пока не увидишь пузырь.

**Меньше — можно.** Все семь поставляемых сосудов уже у́же или ниже слота, это нормально: они
центрируются.

### Проверить свою картинку

macOS, одна команда, печатает всё, что проверяет программа:

```sh
python3 -c "
import struct,sys
d=open(sys.argv[1],'rb').read(26)
assert d[:8]==b'\x89PNG\r\n\x1a\n', 'не PNG'
w,h,bd,ct=struct.unpack('>IIBB', d[16:26])
print(f'{w}x{h} px, {bd} бит, тип цвета {ct}')
print('размер:  ok' if w<=142 and h<=88 else 'размер:  СЛИШКОМ БОЛЬШО')
print('глубина: ok' if bd==8 else 'глубина: НЕ 8 БИТ')
print('альфа:   ok' if ct==6 else 'альфа:   НЕТ альфа-канала')
" Resources/tea_milky_oolong.png
```

Через `sips` (только macOS) — то же самое, кроме номера типа цвета:

```sh
sips -g pixelWidth -g pixelHeight -g hasAlpha -g bitsPerSample Resources/tea_milky_oolong.png
```

### Предупреждение про macOS

**На macOS свой сосуд положить в установленное приложение нельзя.** Бандл подписан, и добавление файла
ломает подпись — программа перестанет запускаться. Переустановка тоже всё затирает: сначала удаляет
папку, потом копирует заново.

Чтобы сосуд оказался в mac-версии, его нужно положить в `Resources/` **в исходниках** и пересобрать.
Поэтому на Windows картинку можно добавить самому, а на mac — нет. Это ограничение, а не недоработка
конфигурации.

Чай без картинки при этом работает: он заваривается, просто в пузыре вместо стакана будет пусто.

## 4. Подпись в меню

Меню показывает `tea_name_<имя>` из языкового пакета. Если ключа нет, показывается само имя из
`tea.conf`.

**Ключа может не быть — и это нормально.** Чтобы заварить, ключ не нужен. Он нужен только чтобы в меню
было написано «Молочный улун», а не `milky_oolong`.

### Windows

Файл `bin/Langpacks/langpack.en.xml` или `langpack.ru.xml`, строка рядом с остальными `tea_name_*`:

```xml
<string id="tea_name_milky_oolong" text="Молочный улун" />
```

### macOS

Те же значения, но в `.strings`, и вручную их писать не надо: файлы пересобираются командой

```sh
python3 tools/gen_strings.py --src /путь/к/исходникам/Windows/bin/Langpacks
```

Ключи живут в самом генераторе (`tools/gen_strings.py`, словари `EXTRA`), и он же раскладывает их по
двум языкам. Правка `.strings` руками переживёт ровно до следующего запуска генератора.

## 5. Пошагово: добавить чай

Пример: **«Молочный улун»**, картинка зелёного чая.

### Шаг 1. Строка расписания

Дописать в **свой** файл `tea.conf` — не в шаблон:

```
milky_oolong, 85, 30, 45, 60, 75
```

Куда именно — см. раздел 1. Шаблон в папке программы трогать бессмысленно: при первом запуске он
копируется в профиль, и дальше читается копия.

Если файл `tea.conf` ещё не существует — он создастся сам при первом запуске программы из шаблона.
Но на macOS он появится только после пересборки, см. раздел 3.

### Шаг 2. Картинка

Скопировать любой готовый сосуд (раздел 3). Windows — сразу, macOS — после пересборки.

### Шаг 3. Подпись

По желанию: ключ `tea_name_milky_oolong` в оба языковых пакета (раздел 4).

### Шаг 4. Перезапустить

Изменения читаются при старте. Не при открытии меню.

### Шаг 5. Проверить

Чай должен появиться в меню **New tea** на той позиции, на которой стоит его строка в файле. Наведите
курсор — подсказка покажет всё расписание: сколько проливов и какие времена.

Если не появился — читайте раздел 6.

## 6. Ошибки и как их увидеть

### Главное правило

Программа **не показывает ошибок на экране**. Никакого окна «ошибка в tea.conf» не будет. Причина
отказа пишется в журнал, а журнал по умолчанию выключен.

Это сделано намеренно: отказ — это ошибка в файле, который никто не должен править руками, и важен он
тогда, когда человек его правит. В повседневной работе это просто тихо.

### Как включить журнал

**Windows:**

```
set EYELEO_DEBUG=1 && EyeLeo.exe
```

**macOS:**

```sh
EYELEO_DEBUG=1 ./EyeLeo.app/Contents/MacOS/EyeLeo
```

Запускать надо именно так, из папки с программой, а не двойным щелчком: переменная окружения доходит
до приложения только в этом случае.

Журнал — `log.txt` в папке из раздела 1. Без переменной он не создаётся вовсе.

### Что может быть отвергнуто

Каждая строка берётся **целиком или отвергается целиком**. Наполовину прочитанного расписания не
бывает.

| Что в строке | Что будет |
|---|---|
| Имя длиннее 24 знаков | строка отвергнута |
| Имя с пробелом, с кириллицей, с заглавной буквы | строка отвергнута |
| Имя, начинающееся с цифры или подчёркивания | строка отвергнута |
| Температура не число, ноль или больше 100 | строка отвергнута |
| Время не число, ноль, отрицательное или больше 3600 | строка отвергнута |
| Больше 8 проливов | строка отвергнута |
| Меньше трёх полей | строка отвергнута |
| Пустое поле между запятыми | строка отвергнута |
| Имя, уже встречавшееся выше в файле | повтор отвергнут, первое определение остаётся |
| **Ничего из перечисленного** | **строка принята** |

**Одна плохая строка не ломает остальные** — они продолжают работать. Откатываются к встроенным
расписаниям только когда негодных строк в файле нет вообще ни одной.

В журнале это выглядит так:

```
tea.conf line 5 rejected: "Green" is not a usable name: one lowercase Latin word, letters, then digits or underscores
tea.conf line 6 rejected: oolong: temperature must be a number over 0 and up to 100
tea.conf line 7 rejected: red: "abc" is not a steep time in whole seconds
tea.conf: 2 teas from tea.conf: jasmine, pu_er2
```

Номер строки — в самом файле, с единицы.

### Быстрая проверка перед перезапуском

Можно не запускать программу, а сначала пропустить файл через ту же проверку. В репозитории лежит
скрипт `tools/checktea.awk`, повторяющий правила программы:

```sh
awk -F, -f tools/checktea.awk путь/к/tea.conf
```

macOS, для файла из контейнера:

```sh
awk -F, -f tools/checktea.awk \
  ~/Library/Containers/local.eyeleo.EyeLeo/Data/Library/Application\ Support/EyeLeo/tea.conf
```

Windows, для файла из профиля:

```
awk -F, -f tools\checktea.awk "%APPDATA%\EyeLeo\tea.conf"
```

Пустой вывод — файл в порядке. Ошибки выводятся с номерами строк, как их же покажет журнал:

```
строка 1: недопустимое имя: Green
строка 4: температура вне (0, 100]: 105
строка 5: недопустимое время пролива: abc
строка 6: больше 8 проливов (9)
строка 7: меньше трёх полей
строка 9: недопустимое имя: пуэр
```

## 7. Вода

Вода **не чай**. Её нет в `tea.conf`, и добавить её оттуда нельзя.

У воды нет расписания выдержки: её не заваривают, её наливают. Это отдельное напоминание со своими
настройками — интервал от 15 до 120 минут и порция от 50 до 250 мл — и со своим стаканом
`tea_water.png`.

Управляется всё это в окне настроек, раздел «Вода».

## 8. Частые вопросы

**Переименовал чай в файле — он пропал из меню и появился снова.**
Так и должно быть. Переименование меняет и имя картинки: было `tea_green.png`, стало
`tea_green2.png`. Если этого не сделали, программа не найдёт сосуд и оставит пустое место.

**Программа дописала в мой файл чай, которого я не хотел.**
Нет, и не допишет. В версиях до 1.5.0 (Windows) такое было — читайте заметки к тем версиям, если
вам важно, чем это кончилось.

**Чая в меню нет, а строка есть.**
Либо в имени есть что-то недопустимое, либо файл не перечитан. Смотрите раздел 6.

**Чай без картинки.**
Работает, в пузыре пусто. Формат файла — раздел 3.

**Можно ли два чая с одинаковым расписанием, но разными картинками?**
Можно, но имена должны быть разными — иначе второе определение отвергнется как повтор.

**Сколько всего чаёв можно добавить?**
Сколько поместится в файл. Ограничения на число чаёв нет. Меню в Windows показывает первые 500, и если
в файле их больше, в журнале будет написано, что показан не весь список.

**Нужно ли пересобирать программу?**
Нет, ни на одной платформе, кроме добавления картинки на macOS.

## 9. Почему на macOS файл так глубоко

Путь получается таким:

```
~/Library/Containers/local.eyeleo.EyeLeo/Data/Library/Application Support/EyeLeo/tea.conf
```

Это не прихоть, а следствие того, что приложение работает **в песочнице macOS**. Песочница разрешает
записывать только внутрь собственного контейнера — папки, которую система выдаёт приложению при
установке. Всё остальное закрыто: и `~/.config`, и `~/Library/Application Support` напрямую.

Дальше путь удлиняется сам собой. `NSSearchPathForDirectoriesInDomains(NSApplicationSupportDirectory)`
для приложения в песочнице возвращает именно
`~/Library/Containers/local.eyeleo.EyeLeo/Data/Library/Application Support`, а не настоящую папку
`Application Support` в домашнем каталоге. Плюс подпапка `EyeLeo`, чтобы рядом лежал `settings.xml`.

**Плюсы такого расположения.** Замена, обновление или удаление программы не трогают ваши настройки и
чаи. Программа не просит у вас ни одного разрешения — вообще. Это же поведение описано в
`entitlements.plist`: там одна-единственная запись, и там же просьба её не добавлять.

**Можно ли положить в `~/.config`.**
Можно, цена известна и она ровно одна строка в `entitlements.plist`:

```xml
<key>com.apple.security.temporary-exception.files.home-relative-path.read-write</key>
<array>
    <string>/.config/eyeleo-mac/</string>
</array>
```

Apple называет такие права *temporary exception* и прямо говорит, что они временные: проверка в App
Store их не пропускает. Для подписанной ad-hoc программы, какой является эта, они работают — я
проверял по профилям песочницы в системе, путь действительно подставляется как `$HOME/<путь>`.

Так что это не «нельзя», а «можно, но это единственное место, где расширяется поверхность приложения».
Что делать — решать вам; текущий вариант безопаснее и переживает переустановку программы сам по себе.
